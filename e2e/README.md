# ตรวจหน้าจอด้วยเบราว์เซอร์จริง

สคริปต์ในโฟลเดอร์นี้เปิดห้องเกมจริง ให้ bot ตอบ แล้ววัดทุกฉากบนหน้าจอหลายขนาด
ตั้งแต่มือถือ 360 px ถึง projector 1080p เพื่อจับของที่ตกขอบ ซ้อนกัน หรือมุดใต้แถบปุ่ม
(งานพื้นฐานข้อ 13 ใน [ROADMAP](../docs/ROADMAP.md))

## ต้องมีอะไรก่อน

1. ลง dependency ของโฟลเดอร์นี้ครั้งเดียว:

   ```bash
   cd e2e && npm install
   ```

2. เซิร์ฟเวอร์ dev รันอยู่ (`npm run dev` ที่ root) — web ที่ 3000, game server ที่ 4000
3. Microsoft Edge บนเครื่อง ถ้าใช้เบราว์เซอร์อื่นให้ชี้ด้วย `E2E_BROWSER=/path/to/chromium`

โฟลเดอร์นี้มี `package.json` ของตัวเองและ **ไม่ได้อยู่ใน workspaces โดยตั้งใจ**
จึงต้องลงแยก แลกกับการที่ `npm ci` และ `npm test` ที่ `deploy/deploy.sh` รันบนเครื่อง production
ไม่มีทางดึง library ของเบราว์เซอร์ขึ้นไปบนนั้น

`playwright-core` เป็นของโฟลเดอร์นี้เอง ส่วน `socket.io-client` ยืมจาก game server
เพื่อให้ client ที่ใช้เข้าห้องเป็นเวอร์ชันเดียวกับที่ server build ไว้เสมอ

## คำสั่ง

```bash
npm run e2e              # สวีปเต็ม: 16 ขนาดจอ × 2 เกม แบ่งรันทีละ 4 (~15 นาที)
npm run e2e:slider       # เฉพาะหน้าเฉลยของ slider
npm run e2e:reveal       # เฉพาะหน้าเฉลยของ quiz / poll / true-false
```

รันกับ production ได้ด้วยการใส่ base url:

```bash
node e2e/slider-fit.mjs --base=https://dmhub.mfec.dev/icebreaker
```

ตัวเลือกอื่นอยู่ในหัวคอมเมนต์ของแต่ละไฟล์ เช่น `--shots` (เก็บภาพ),
`--only=` (เลือกเกม), `--views="host 360,stage 360"` (เลือกเฉพาะบางจอ)

## ทำไมต้องแบ่งรันทีละ 4 จอ

**หนึ่งจอคือหนึ่งหน้าเบราว์เซอร์จริง** ถ้าเปิดพร้อมกันเกินจำนวน core ของเครื่อง
หน้าที่ไม่ได้ CPU จะวัดผิดจังหวะ บนเครื่อง 8 core ที่วัดไว้:

| เปิดพร้อมกัน | timer ในหน้าเว็บเพี้ยน | ผล |
|---|---|---|
| 13 หน้า | ถึง 2,520 ms | พลาดช่วง stamp ที่มีแค่ 1 วินาที → ฟ้องผิดว่าเจอบั๊ก |
| 4 หน้า | 8–24 ms | สะอาด ทำซ้ำได้ |
| 2 หน้า | 1–14 ms | สะอาด |

`sweep.mjs` จึงแบ่งเป็นชุดละ 4 โดยแต่ละชุดเล่นเกมของตัวเอง ปรับได้ด้วย `--batch=N`
เครื่องที่ core เยอะขึ้นได้เลขสูงขึ้น **ตัวเลขที่ฟ้องว่าพังโดยที่เปิดหลายหน้าเกินไป
มักไม่ใช่บั๊กของแอป ให้ลดจำนวนหน้าแล้วรันซ้ำก่อนเสมอ**

`slider-fit.mjs` ก็แบ่งเหมือนกัน (`--batch=N` ค่าเริ่มต้น 4) ตอนที่มันเปิดทั้ง 16 จอพร้อมกัน
มันพังเองเป็นครั้งคราวโดยที่แอปไม่ได้ผิดอะไร: เครื่องไม่ว่างจน socket ของ Host หลุด
แล้วมันก็กด `host:next` ใส่ห้องที่ไม่ฟังแล้วไปอีก 2 นาที ก่อนจะฟ้องผิดว่าค้างที่ฉากไหน

`sweep.mjs` อ่านรายชื่อจอจาก `narrow-ui.mjs` โดยตรง เพิ่มจอใหม่ที่เดียวพอ

## เดินเกมจาก Host ในสคริปต์

ห้องเดินเองเกือบหมด มีแค่ **lobby, หน้าเฉลย และ leaderboard** ที่รอให้ Host กด
ส่วนการ์ดชื่อรอบไปต่อเองเมื่อครบเวลา และคำถามจบเองเมื่อหมดเวลาหรือทุกคนตอบแล้ว

การกดแต่ละครั้งแนบ `step` ของฉากที่เห็นตอนกดไปด้วย server จะไม่รับการกดที่ step ไม่ตรง
(กันไม่ให้กดทะลุไปฉากถัดไป) ดังนั้นสคริปต์ต้อง **กดครั้งเดียวแล้วรอจน step เปลี่ยนจริง**
ห้ามกดซ้ำเป็นจังหวะ เพราะถ้าห้องไม่ขยับ การกดซ้ำก็ไม่ช่วยอะไรอยู่ดี และจะกลบสาเหตุจริง
ข้อความ error ทุกอันจึงพ่วงสถานะห้องไว้ (`phase`, `step`, socket ของ Host ยังต่ออยู่ไหม)

## แต่ละไฟล์ตรวจอะไร

| ไฟล์ | ตรวจ |
|---|---|
| `narrow-ui.mjs` | ทุกฉากทุกประเภทคำถาม ใน 2 เกม: เกมปกติที่ทุกฉากต้องพอดีจอ และเกมที่ทุกช่องยาวที่สุดเท่าที่ editor ยอม ซึ่งเลื่อนได้แต่ห้ามตกขอบ |
| `sweep.mjs` | ตัวรัน `narrow-ui.mjs` ทีละชุดแล้วรวมผล |
| `slider-fit.mjs` | หน้าเฉลย slider: ตัวเลขพอดีช่อง ไม่ชนกัน ไม่มุดใต้ dock |
| `reveal-fit.mjs` | หน้าเฉลยแบบแท่ง: แท่งกับการ์ดสถิติอยู่ในขอบ ตัวเลขอยู่กลางแท่ง รวมกรณีตัวเลขยาวที่สุด (1,000 คน) |

## บน CI

| workflow | เมื่อไหร่ | ทำอะไร |
|---|---|---|
| [`checks.yml`](../.github/workflows/checks.yml) | ทุก push และ PR | typecheck + unit test + build บน Node 20 และ 22 แล้วเล่นเกมจริงด้วยบอท 200 คน (`npm run crowd`) — ไม่ใช้เบราว์เซอร์ |
| [`screens.yml`](../.github/workflows/screens.yml) | ทุกคืนตี 2 (ไทย) และสั่งเองได้ | ตัวตรวจในโฟลเดอร์นี้ทั้งหมด: `e2e:slider`, `e2e:reveal` และสวีปเต็มแบบ `--batch=2` |

runner ของ GitHub มี 4 core จึงตั้ง `--batch=2` ไว้ ส่วนเบราว์เซอร์ดึง Chromium
เวอร์ชันเดียวกับ `playwright-core` ใน `package.json` ของโฟลเดอร์นี้ (อ่านเลขจากไฟล์นั้นตรงๆ
ไม่ต้องแก้สองที่) แล้วชี้ด้วย `E2E_BROWSER` CI ยกแอปแบบ production build ขึ้นมาจริง
คู่กับ Postgres เป็น service จึงได้ทดสอบ migration ไปด้วย ถ้าพังจะเก็บภาพและ log
ของทั้งสองเซิร์ฟเวอร์เป็น artifact ไว้ 7 วัน

## ข้อควรรู้

- **ไม่ได้อยู่ใน workspaces โดยตั้งใจ** `npm test` ที่ root รันแบบ `--workspaces --if-present`
  และ `deploy/deploy.sh` เรียกมันบนเครื่อง production การแยกออกมาทำให้เครื่อง production
  ไม่มีทางพยายามเปิดเบราว์เซอร์ตอน deploy
- ของตกแต่งที่ `aria-hidden="true"` ได้รับการยกเว้นจากการเช็กขอบ เพราะกล่องของมัน
  เช่น ลำแสงสปอตไลต์บนโพเดียมที่หมุนรอบหัวตัวเอง ยื่นออกนอกฉากได้โดยที่สีที่วาดจริงยังถูก clip อยู่ข้างใน
- ภาพและค่าที่วัดได้ลงในโฟลเดอร์ข้างๆ (`narrow-shots*/`, `reveal-fit-*/`) ซึ่ง `.gitignore` กันไว้แล้ว
